**book-04** Is it worth caching a prompt prefix that I'm only going to send once?

**boundary-01** What does max_tokens do, and what happens to the response if the ceiling is hit?

> `max_tokens` is a required, hard ceiling on how much the model may produce in one response, measured in output tokens. It is not a suggestion. If the model reaches it, the response simply stops, mid-sentence if necessary, and `max_tokens` is reported as the stop reason. The result is a truncated answer that looks like an answer, with its text populated but cut off mid-thought.


**boundary-02** The weights were fitted on text gathered up to some point in time: what is that point called, and what does the model know after it?

> That point is called the training cutoff. After it the model knows nothing, and it cannot tell "after my cutoff" from "does not exist". So it won't say "I don't know" about something newer, such as a library released last month, but will give a fluent, plausible-sounding answer.


**boundary-03** The book says sycophancy is not politeness and not indecision. What is it then, and where does the tendency come from?

> Sycophancy is a model's tendency to move towards the position it believes its interlocutor holds, rather than towards the position the evidence supports. It is a learned pattern: text in which a speaker accommodates a disagreeing counterpart is very common. Agreeable continuations were also reinforced during training because human raters preferred them.


**boundary-04** What is fail-first verification, and why does it matter more when a model writes the code or the tests?

> Fail-first verification is proving that a test fails when the behaviour it guards is broken, before trusting it to guard anything: break the code, run the test, see red, restore, see green. It matters more with a model because a test that cannot fail is exactly what an optimiser under pressure produces when asked to make a suite pass. A model asked to "add tests for this change" produces tests that check nothing at a noticeable rate, and they look like real ones, so the only way to tell is to break the code and see whether they notice. The book also notes that in one author's experience, roughly one time in five a heavily relied-on test does not go red when the code it guards is broken.
