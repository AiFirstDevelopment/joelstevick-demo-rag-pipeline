**book-19** Why does the book recommend having the model grade its own work as the main quality check?

> The book does not recommend this; it says the opposite. Its rule is that nothing grades its own work, because a grader whose only input is the thing being graded is a text generator with a strong prior towards approval. A model asked whether its own work is correct says yes either way, so the answer tells you nothing. What works instead is a check whose outcome does not depend on the model's opinion of its own output.

**boundary-03** The book says sycophancy is not politeness and not indecision. What is it then, and where does the tendency come from?

> Sycophancy is a model's tendency to move towards the position it believes its interlocutor holds, rather than towards the position the evidence supports. The book ties it to a grader that has been told your conclusion, such as by reading your change summary, and it shows the model folding when told someone reached the opposite view, with no argument or evidence given. It is worst when a grader is needed most.


**boundary-04** What is fail-first verification, and why does it matter more when a model writes the code or the tests?

> Fail-first verification is proving that a test fails when the behaviour it guards is broken, before trusting it to guard anything: break the code, run the test, see red, restore, see green. It becomes non-negotiable when a model writes the code or the tests, because a test that cannot fail is exactly what an optimiser under pressure produces when asked to make a suite pass. Such tests are hard to spot by reading, since they look like real ones, so the only way to tell is to break the code and see whether they notice.
