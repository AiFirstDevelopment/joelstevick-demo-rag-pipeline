**book-11** What's the catch with copying a shared checker script into every repo so CI can run it?

> The catch is that a vendored copy is frozen on the day it was made. If you later improve the guard, add a rule or fix a bug, every repo that copied the old version keeps enforcing the old rules while still reporting green. **book-19** Why does the book recommend having the model grade its own work as the main quality check?

> The book does not recommend this; its rule is that nothing grades its own work, including the model. It says a grader whose only input is the thing being graded is a text generator with a strong prior towards approval, because judging is the same kind of operation as generating and the likely next text is PASS. A model asked whether its own work is correct will usually say yes, so an answer that never varies tells you nothing. What the book recommends instead is checks whose outcome does not depend on the model's opinion of its own output.


**book-20** Why does the book say temperature 0 makes the model fully deterministic?

> The book does not say that. It says the opposite: temperature 0 does not make the model deterministic. At 0 the most likely candidate is taken every time, so only the selection rule becomes deterministic. Identical requests at temperature zero can still produce different text, for reasons in floating-point arithmetic and server-side batching that are outside your control.


**book-21** Why does the book say a twenty-round agent loop costs about twenty times a single request?

> The book does not say that; it says a twenty-round loop costs closer to two hundred times one request, not twenty. The reason is that you send the entire conversation on every request, so each round re-sends everything before it plus the new material. In its Chapter 4 example, a twenty-turn run over a transcript ending at 40,000 tokens sends about 400,000 input tokens, because the average turn carried half the final transcript. So cost is quadratic in turn count, not linear.

**boundary-03** The book says sycophancy is not politeness and not indecision. What is it then, and where does the tendency come from?

> Sycophancy is a model's tendency to move towards the position it believes the other party holds, rather than towards the position the evidence supports. It comes from a learned pattern: text in which a speaker accommodates a disagreeing counterpart is very common. Agreeable continuations were also reinforced during training because human raters preferred them.


**boundary-04** What is fail-first verification, and why does it matter more when a model writes the code or the tests?

> Fail-first verification is proving that a test fails when the behaviour it guards is broken, before trusting it to guard anything: break the code, run the test, see red, restore, see green. It becomes non-negotiable once a model writes the code or the tests, because a test that cannot fail is exactly what an optimiser under pressure produces when asked to make a suite pass. Such tests are hard to spot by reading, since they look like real ones, and a model asked to "add tests for this change" produces them at a noticeable rate. The only way to tell is to break the code and see whether they notice.
