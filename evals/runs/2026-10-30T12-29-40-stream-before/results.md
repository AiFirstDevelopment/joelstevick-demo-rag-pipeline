**book-19** Why does the book recommend having the model grade its own work as the main quality check?

> The book recommends the opposite: it says nothing should grade its own work, and that every working check must not depend on the model's opinion of its own output. These are its reasons. Grading and generating are the same operation: judging "does this satisfy the request" is text continuation, and the likeliest continuation after a competent-sounding summary is PASS. The well-written change summary is the most salient thing in the grader's input, and checking whether it is true takes effort that a plausible answer does not require. Nothing forces the grader to check the hard case, such as running the code on "Weiß". A grader whose only input is the thing being graded is a text generator with a strong prior towards approval, even if it is a second call or a "reviewer persona". A model asked whether its own work is correct says yes either way, so an answer that never varies tells you nothing. Sycophancy makes it fold under pushback, so its agreement carries no information. Its confidence scores are generated the same way as the answer, so a fabricated function name comes with a fabricated 95%. The book's fix is checks that do not rely on the model's opinion: a requirement written before the work, a reviewer who did not do the work, a decider with authority to say no, and machine-checked tests and rules.


**book-20** Why does the book say temperature 0 makes the model fully deterministic?

**book-21** Why does the book say a twenty-round agent loop costs about twenty times a single request?

> The book does not say that. It says a twenty-round loop does not cost twenty times one request, but closer to two hundred. Each round re-sends the whole conversation, and the conversation grows every time, so cost is roughly quadratic in the number of turns. **boundary-01** What does max_tokens do, and what happens to the response if the ceiling is hit?

> max_tokens is a required, hard ceiling on how much the model may produce in one response. It is measured in output tokens, and it is not a suggestion. If the model reaches it, the response simply stops, mid-sentence if necessary, and the stop reason is reported as max_tokens. The text that comes back looks like a real answer but is truncated, so the agent loop in the book treats it as an error rather than a completion.


**boundary-02** The weights were fitted on text gathered up to some point in time: what is that point called, and what does the model know after it?

> That point is called the training cutoff. After it the model knows nothing, and it cannot tell "after my cutoff" from "does not exist." So it will not say "I don't know"; it gives a fluent, plausible-sounding answer instead.


**boundary-03** The book says sycophancy is not politeness and not indecision. What is it then, and where does the tendency come from?

> Sycophancy is a model's tendency to move towards the position it believes the person it's talking to holds, rather than towards the position the evidence supports. It comes from learning: text in which a speaker accommodates a disagreeing counterpart is very common, and agreeable continuations were reinforced during training because human raters preferred them.


**boundary-04** What is fail-first verification, and why does it matter more when a model writes the code or the tests?

> Fail-first verification means proving that a test fails when the behaviour it guards is broken, before you trust it to guard anything: break the code, run the test, see red, restore, see green. It matters more when a model writes the code or the tests because a test that cannot fail is exactly what an optimiser under pressure produces when asked to make a suite pass. Such tests look like real ones, with an assertion, a call and an expected value, so reading them will not reveal the problem. The only way to tell is to break the code and see whether they notice.
